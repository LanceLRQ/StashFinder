# 查询性能基线

简体中文 | [English](query-performance.en.md)

2026-11-05，Windows 开发虚拟机、约 8 GiB RAM、Rust 1.94 Release。使用生产查询匹配器、完整结果排序、查重、分页和取消代码；没有截取前 200 条来缩短计算。以下是实测，不是性能承诺。

## 数据与方法

- 分别构造 100 万和 1000 万条文件记录，分布到 12 个文件系统缓存。名称含中英文，父路径含多级中文目录，包含真实零字节及 MiB/GiB 级大小、重复名称／大小和完整时间字段。
- 每个分区共享一个深层父目录。此样本不覆盖大量分支目录、真实长 ID、元数据空值、冷 SQLite 加载、真实磁盘索引或完整 GUI/后台空闲资源。未知值、目录与硬链接另有行为测试。
- 普通查询重复 20 次，以排序后的第 19 个值计算 nearest-rank P95；重查询百万规模 3 次、千万规模 1 次，只报告样本范围，不能称作 P95。
- 返回数量与独立生成公式核对。每次计时包括完整匹配、全局分组／排序和实体化首个 100 条；不包括 IPC、GUI 渲染和内容读取。
- 数据在进程内构造，不是冷启动或完整服务内存测量。虚拟机调度与内存回收影响结果，千万构造后的工作集出现过回收。

## 结果

| 项目 | 100 万条 | 1000 万条 |
|---|---:|---:|
| 缓存构造 | 0.75 s | 9.43 s |
| 缓存私有提交 | 249,765,888 B（约 238 MiB） | 2,488,016,896 B（约 2.32 GiB） |
| 普通子串查询 P95，1 条命中 | 220 ms | 1,997 ms |
| 高命中查询及全局排序 | 1.30–1.48 s | 31.69 s（1 次） |
| 同大小查重 | 1.93–2.93 s | 53.17 s（1 次） |
| 同名且同大小查重 | 2.23–2.56 s | 38.46 s（1 次） |
| PCRE2 查询，1 条命中 | 0.54–0.69 s | 6.86 s（1 次） |
| 查询过程峰值工作集 | 约 261 MiB | 约 2.54 GiB |
| 发出取消信号后的整体返回时间 | 172 ms，含 150 ms 预设等待 | 290 ms，含 150 ms 预设等待 |

建议预算的参考环境为 16 GiB RAM，本机约 8 GiB，因此不能把上述结果当成同环境达标测试。即便如此，本机普通查询超过建议的 150/300 ms 预算，千万缓存本身也超过 2 GiB 服务私有提交目标；当前未证明达到这些预算。全量结果仍另需条目引用向量，索引更新时保留旧快照也会增加峰值。

本轮已把字符串元数据改为数值缓存、复用大小写折叠名称，并只在分页时构造路径与响应对象。最初的 ASCII 百万样本缓存约 426 MB，普通查询约 1.8 s；优化后同一 ASCII 样本约 250 MB、约 0.1 s。中英文最终数据的表格结果应优先参考，不能挑选较快的中间成绩宣传。

后续仍需优化候选检索、结果排序与缓存布局，并在参考硬件测量完整服务、冷数据库加载、GUI 进程和后台空闲占用。当前完整性、全范围查重和明确取消优先，不以截断结果换取速度。

## 复现

从仓库根目录执行，避免同时构建、跑浏览器测试或扫描磁盘：

```powershell
cargo build -p stashfinder-store --bin query-baseline --features query-bench --release --locked
.\target\release\query-baseline.exe 1000000
.\target\release\query-baseline.exe 10000000
```

输出逐行 JSON，含全部耗时样本、计数、内存和取消结果。基准不创建目录库或修改源盘。`query-bench` 仅显式启用，日常应用不包含合成缓存生成入口。
