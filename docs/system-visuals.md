# 系统图标与缩略图

[English](system-visuals.en.md)

文件列表显示 Windows 关联格式图标。文件夹、应用程序和快捷方式等条目会在在线时按需读取专属图标；获取失败时保留通用类型图标。普通类型图标不需要访问源文件，离线记录也能显示。

打开预览窗格并选择一个文件后，程序先读取本地图片缓存，再查询 Windows 缩略图缓存；没有缓存时允许 Windows 生成缩略图。图片、视频、文档等格式的支持取决于本机安装的 Windows 缩略图提供程序。StashFinder 不自行解析文件内容或抽取视频帧，也不批量预生成整个分区的缩略图。

离线时只读取本地图片缓存。有缓存的预览标记为“历史缓存”；没有缓存时显示类型图标和离线状态。文件信息仍来自分区索引，缩略图获取失败不会影响目录浏览或搜索。多个文件选中时显示元数据汇总，不生成整组预览。

## 缓存设置

在“设置 → 缓存”中查看已用空间、容量上限和当前处理状态。默认上限为 **2 GB（2,000,000,000 字节）**，支持修改。

- 图标和缩略图以独立 PNG 文件保存，不写入 SQLite 索引。
- 达到上限时优先淘汰最久未使用的图片；降低上限会立即整理。单张图片超过额度时可以显示，但不落盘。
- 占用按应用缓存图片的文件字节数计算，不代表文件系统的实际分配空间；原子写入期间可能短暂额外占用临时空间。
- “清空缓存”需要在程序内确认，只清理应用图片，保留容量设置、分区登记、索引和源文件。下次查看文件时会重新按需获取图片。
- 设置页显示实际等待数、执行数以及整理批次的完成数。单个 Windows 缩略图调用不提供可靠百分比，因此只显示阶段。

Windows 上，图片目录为 `%LOCALAPPDATA%\io.github.lancelrq.stashfinder\visual-cache`，配置为 `%APPDATA%\io.github.lancelrq.stashfinder\visual-cache.json`。从打包启动器运行时，Windows 可能重定向这些路径；它们与后台的分区索引目录相互独立。不要将整个应用数据目录当作图片缓存删除。

## 一致性与限制

图片键绑定分区、文件系统实例、条目身份、索引记录的大小和时间以及请求尺寸，不包含盘符。换盘符不要求重新生成全部图片；索引记录更新后使用新的图片键。图片提取前后核验在线实体身份，旧选择或已取消请求的结果不会覆盖新的预览。

图片是历史快照，不能证明离线文件现在仍存在。应用根据索引中的元数据版本判断缓存是否可复用，不进行内容哈希校验；尚未同步到索引的外部修改要等索引更新后才会使缓存失效。

类型图标在每次启动后首次使用时重新查询系统关联。缩略图提供程序可能缓慢、返回空结果或报错；切换选择会取消排队请求，已经进入 Windows 的调用可能仍需等待返回。程序限制同时执行的图像任务，不尝试强行终止第三方系统提供程序。

## 开发验证

自动检查入口见 [开发指南](development.md)。专项测试：

```powershell
cargo test -p stashfinder-windows --test visuals --locked
cargo test -p stashfinder-desktop --locked
npm.cmd --prefix ui test -- --run src/Visuals.test.tsx src/CacheSettings.test.tsx
```

Windows 接口测试只在临时目录生成样本，验证系统类型图标、真实缩略图生成和后续系统缓存命中。桌面端测试验证离线不访问提供程序、盘符无关的缓存键、元数据变化、取消、清空期间的旧结果隔离、额度及实际整理进度。

GUI 验收应在已登记的可丢弃测试分区进行：选择图片、未知格式、目录和应用程序；等待图片生成后卸载测试盘，核对离线历史预览；重开界面及重新挂载后复验。修改测试图片并等待索引更新，核对预览刷新。最后在设置页调整额度、取消及确认清空，核对配置持久化、占用和源文件。自动检查不能替代不同 Windows 版本、系统扩展和设备上的实机验证。
